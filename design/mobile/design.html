Design notes

Navigation model

  • Four tabs: Explore, Search, Mempool, Settings. iOS uses a TabView tab bar; Android a Material 3 NavigationBar with the gold-tint active pill.
  • Chain is global state, chosen in the teal band with a two-segment control, Bitcoin Cash first, then Nexa. It scopes Explore, Search and Mempool and is remembered.
  • Detail screens push on the current tab’s stack (block → tx → address → token). Back is the system gesture/button; every detail screen has Share with the matching explorer.nordiccrypto.no/<chain>/<kind>/?… URL.
  • Deep links: the same web routes open the app (Universal Links / App Links), so a shared web link and an app link are one thing.
  • CAPD is a Nexa-only entry in Explore and a segment in Mempool; on Bitcoin Cash it is not shown.

Components

  • Band header: teal #1E3A45 with the 45°/−45° diamond lattice, key-shield + “Nordic Crypto” wordmark, search field, chain control.
  • Stat card (3 px foam top rule, gold when pressed), list card (ledger rows collapse to two-line rows), hash row with Copy, facts list, flow (inputs ↓ outputs), chip, callout (warm), source line with live dot.
  • Money: coin amount in mono, fiat beneath in muted text. Fee rates carry “for a ~250 byte transaction”, as on the web.
  • States: loading skeleton, unreachable (lists each server that did not answer + Try again), nothing found, empty mempool, price unavailable.

Live data only

  • The app reads Electrum/Fulcrum (BCH) and Rostrum (Nexa) over WSS, with the same server list and fallbacks as lib/chains.ts, and quotes from CoinGecko (bitcoin-cash, nexacoin).
  • No bundled or cached-as-current figures. With no reply the UI shows which source did not respond, never a stand-in number. Cached values, if added later, must carry their age.
  • No fiat quote → amounts stay in coins and the price card says “Unavailable”.
  • Every data screen ends with “Read from <server> · n s ago”.
  • Figures on this board are layout specimens to show type and spacing. They are not chain data, and the QR encodes a dummy string.

Typography

  • Display: Cormorant Garamond 700, for screen titles, heights, balances, stat figures (28–44 pt).
  • UI: Schibsted Grotesk 400–700, body 16 pt, rows 15 pt, labels 13 pt.
  • Data: IBM Plex Mono 500, for hashes, addresses, amounts, eyebrows (11 pt, +0.12em caps). Tabular lining numbers everywhere.
  • Bundled fonts (OFL) on both platforms. Text styles map to Dynamic Type (iOS) and sp scaling (Android); layouts reflow to 200 %.

Accessibility

  • Contrast follows the web palette: body text ≥ 7:1 on surface, muted text ≥ 4.5:1 in both themes. Gold is decoration on teal; gold-ink #8A5A0C is used for gold text on light.
  • Hit targets 44 pt (iOS) / 48 dp (Android). The chain control is a radio group with a pip and text label, so colour is never the only cue.
  • Hashes are read as “hash, starts 0000a7, ends e1f4” by VoiceOver/TalkBack, with the full value behind Copy. Ages update politely, not as live-region spam.
  • Reduce Motion stops the skeleton sheen. The error state is announced as an alert.

Shared design system (SwiftUI + Compose)

  • One token source (tokens.json, generated from app/globals.css) builds NCColor/NCFont/NCSpace for SwiftUI and an NCTheme (ColorScheme + Typography + Shapes) for Compose.
  • Radii 12/7, spacing 4-pt grid (8, 12, 16, 22), shadow from --shadow. Light/dark from the same pairs as :root / [data-theme=dark].
  • Same component names on both sides: BandHeader, ChainSwitch, StatCard, LedgerList, HashRow, FactsList, TxFlow, MoneyText, SourceLine, StateView(.unreachable/.empty/.loading).
  • Shared core (chain list, protocol parsing, formatting from lib/format.ts) via Kotlin Multiplatform, or ported 1:1 with the web’s test fixtures as the contract.
